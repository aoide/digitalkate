Summary

Overview

With this update, the AuthorPro plugin to Arbortext has a streamlined check in process for documents with less dialogs and the additional option to assign documents after checking them in.

Role/Responsibility

UI Designer

Users

Authors

Scope

Add the ability to assign documents

Constraints

The java application itself

Results

The end result removed two time consuming activities from our author’s workflow: having to open Manager to assign documents and having to complete multiple clicks to check in a document. It saved time on a daily task and removed existing pain points for them.

Analysis

The first thing I wanted to do was to understand how the current check in process worked. I opened the application and completed various scenarios of checking in documents, taking screenshots along the way. This allowed me to create a flow diagram of the current process. I needed to understand the full process before I could interject into it.

From here, I noted some issues. The first was there were a lot of dialogs, which netted a lot of clicks. Another issue was that all of these dialogs displayed for each document checked in. 6 dialogs a cycle over 2 documents to check in is a little over 12 clicks to check in.

With the check in process being problematic as it was, I started to look at what minor improvements I could make. I diagramed out an ideal workflow pattern, taking into consideration there could be multiple documents being checked in at once. A huge consideration was reducing the number of clicks without losing any information.

Analysis

Mockups

Starting with a list of data that the application needs to check in a document, I added fields to an empty dialog frame. For check in, this was the list of documents being checked out so the user could verify their selections. For assign, this was setting up the user from a selected workflow to assign the document to. The assign fields were moved into the order that made the most sense for the flow: select a workflow, then select a user from that workflow.

A results dialog was created by removing the previous check in count and confirmation dialogs. Instead of using a dialog per document, I used one dialog at the end to summarize all the confirmations (both successful and issues).

After feedback and discussion, a few changes were made. The dialog went from having versions of single document check out and multi-document check out to only one version that could accommodate multi-document check out. The assign fields had conditions that would make them unavailable. Initially this was hidden behind the checkbox, but they were moved to before the checkbox, while making it disabled.
