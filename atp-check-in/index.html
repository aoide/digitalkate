Overview

Boeing S1000DauthorPro is an authoring plug-in for Arbortext. The plug-in was written in java and xml and supports checking documents in and out of S1000Dmanager (a document management tool that supports sending documents through workflows as they are authored) as well as assisting authors in complying with the S1000D authoring specification.

With this update, the check in process was streamlined to remove multiple dialogs and clicks. Additionally, the ability to assign documents to another user in another workflow was added.

Analysis

The first step was to understand how the current check in process worked. I needed to understand the full process before I could interject into it. To assist with this, I created a flow diagram of the current screen.

The main issue that stood out to me was that there were a lot of sub dialogs, and these dialogs displayed for each document checked in. There were 6 mains dialogs to check in, and if a user had 3 documents to check in, they’d have 12 clicks to complete the process.

User Flow Diagram

Using the flow diagram created in the analysis phase, I created a second file and made my modifications to create an ideal workflow pattern. I combined dialogs where it was reasonable to do so. A huge consideration was reducing the number of clicks without losing any information.

I gave both of these to development as a guide for what dialogs to remove and add and help give them an idea of how the new flow would work.

Mockups

Starting with a list of data that the application needs to check in a document, I added fields to an empty dialog frame. The fields were moved into the order that made the most sense for the flow: select a workflow, then select a user from that workflow.

A results dialog was created by removing the previous check in count and confirmation dialogs. Instead of using a dialog per document, I used one dialog at the end to summarize all the confirmations (both successful and issues).

After feedback, the dialog went from having versions of single and multi-document check out to only one version that could accommodate multi-document check out.
