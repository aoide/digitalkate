Summary

Overview

The added ability of configurable columns to our document list allows users to customize their document list to their personal preferences.

Role/Responsibility

UI Designer & Front End Developer

Users

All users of the system: project managers, authors, QA

Scope

Add the ability to configure columns to the user’s preference

Constraints

  • Minimal developer effort
  • Time boxed (1 mo)
  • Implementation couldn’t interfere in normal operations

Results

Columns for data lists are now customizable per user. Using drag and drop of columns, authors can reorder them to their desired preference. They can also remove them from view if they feel the data the column providing isn’t valuable to them personally. They can also resize the column, giving it more space (particularly helpful on columns with long data values).

Analysis

Summary

Analysis

For this task, the request was pretty straight forward. We’ve had complaints about not being able to see all the data, wanting to have different columns displayed, and generally wanting to be able to modify the presentation of the list.

The request brought forward some problems with our responsive solution, particularly in regards to how the columns ‘dropped’ into an expanded area. While it was fine for tables for a small number of columns, it was problematic for larger column sets. Authors couldn’t find the dropped columns and had trouble understanding what was happening to the ‘disappearing’ data cells.

The core of what they wanted: the ability to display all the columns and change the order in which they appeared. Different authors had different preferences.

Analysis

Mockups

Starting with the base documents list in the Inbox, I needed to add 4 new features: removing columns, adding columns, and resizing columns, then a reset after.

The first few iterations included utilizing menus, dialogs, and screens. It was trying to answer the question of how can I display all the columns that are available without getting in the way. This would probably be a one and done type task.

I also played around with including more columns and setting of items in the expanded area, but this started to go down a bit of a rabbit hole and stayed away from both minimum viable functionality and was outside the scope of something I could do on my own.

The solution I settled on was for a menu. It allowed for multiple columns to be included for re-addition as well as a reset button.

Resizing was a typical resize bar mechanism.

Reflection

While users testing still needs to be completed, some initial changes I can see in another iteration are to make it more extensible, allowing for more columns later on. There were some columns permanently in the expanded section I’d like to include. Also there are other data columns we don’t show at all as well as the ability to designate what should be in the expanded section over a displayed column.

Next questions to start considering is turning on and off the configurability so there’s an edit mode and how users take to the drag and drop feature, both in using it and discovering the feature itself.
