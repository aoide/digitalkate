Summary

Overview

With this update, Manager received an upgraded Group screen and the ability to create custom groups with custom permissions, allowing for finer grain control over which users have access to which functionality.

Role/Responsibility

Primary UI Designer & Front End Developer

Users

Project managers, system admins

Scope

  • Add the ability to set permissions for different functionality to users by group
  • Remove old group screen technical debt

Constraints

Time boxed (3mo)

Results

Project managers and system administrators can now create groups of users to give specific functionality access to.

Analysis

A few questions I took to our program liaisons (people who work directly with our customers and know their problems) and site system admins (people who run the application on site) were along the lines of:

  • Who typically applies users to the current groups?
  • How often?
  • What are the job titles and roles of the current users of the system?
  • What kind of tasks do they perform?
  • Is there anything the current permission groups give you trouble with or you don’t like?
  • Is there anything about the current permission groups you do like?

From there, with the help of the rest of the UX team, we took inventory of all the functions in the system. Grouped some into a single permission where it was reasonable to do so, then grouped them by commonality (eg. “Reports” or “Content” or “Projects”). Ideally the grouping would have been done by a few users, but we were working under program constraints.
